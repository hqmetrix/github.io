Case study

What if QRDA I cannot be produced by the EMR? Use C-CDAs

A practice's EMR had no usable patient-level quality export. Clinical documents were the fallback.

Case Studies · Anonymized · Last checked November 17, 2026

← Case Studies

Problem

The EMR could not generate patient-level QRDA files, and its own measure report could not be tied to individual patients. Without patient-level data the ACO could not deduplicate patients, check completeness or build gap lists for that practice.

Required Data

  • Problems, medications, results, vital signs, procedures and immunizations
  • Encounter dates and types
  • Exclusion and exception reasons
  • Patient identifiers that match the rest of the ACO

FHIR Sources

The EMR did not expose the needed FHIR resources, so C-CDA documents (CCD summaries) were collected per patient. Where a FHIR API was available later, its resources replaced the document parsing for the same elements.

QRDA Generation

  1. Collect C-CDAs for the eligible population across the measurement period.
  2. Parse sections into standard clinical data: problems, results, vitals, procedures, medications, immunizations.
  3. Map codes to the measure value sets.
  4. Calculate the measures or create QRDA I files from the mapped data.
  5. Aggregate with data from other sources into QRDA III or QPP JSON.

Validation

  • Check what the C-CDAs lack: encounter types, dates, negation and exclusion reasons.
  • Compare results with the EMR's own report on a sample and explain differences.
  • Run QRDA files through CMS's validation tools.
  • Confirm counts against eligible patients to check completeness.

Submission

The practice's data was included in the ACO-level calculation and submitted like any other source. Documentation of the method and its known limits was kept with the validation notes.

Common Errors

  • Assuming a C-CDA carries every data element a measure needs
  • Dates in the document that are not the clinical event date
  • Free-text results with no code
  • Documents generated once and never refreshed
  • Patients missing because a document was not produced for them

At a glance

  • Setting: practice group with a limited EMR
  • Fallback: C-CDA documents mapped to measure data
  • Risk: gaps in what C-CDAs carry
  • Details are generalized. No client names, and no results are claimed that are not described here.
