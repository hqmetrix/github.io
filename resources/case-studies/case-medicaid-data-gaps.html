Case study

Improving quality measures for a Medicaid plan by identifying data gaps

A plan's rates looked low. Much of the shortfall was missing data, not missing care.

Case Studies · Anonymized · Last checked November 17, 2026

← Case Studies

Problem

Quality rates for several measures were below target. The plan could not tell which members truly missed a service and which had received it but had no record reaching the plan, such as a screening done by an outside provider or a result held in an EHR.

Required Data

  • Eligibility and enrollment history
  • Medical and pharmacy claims and encounters
  • Clinical results and screening data from providers and exchanges
  • Supplemental data: immunization registries, lab feeds, social needs screening
  • Provider roster and attribution

FHIR Sources

  • Patient and Coverage from enrollment systems
  • ExplanationOfBenefit and Claim for adjudicated services
  • Observation and DiagnosticReport from provider FHIR APIs and exchange partners
  • Immunization from registries
  • Bulk data export for full-population pulls where partners support it

QRDA Generation

Not the main path here. Plan measures usually follow the program's own specification, so the work focused on getting clinical data into the plan's measure engine as supplemental data. QRDA I can still serve as an intake format when a provider can produce it. Check which specification and file formats your program requires.

Validation

  • For each measure, split non-compliant members into: no service found anywhere, service found in supplemental data, and service found but not coded to the measure.
  • Sample-check a set of members against provider records.
  • Track how much each new data source moves each rate.

Submission

Improved supplemental data was submitted through the plan's normal reporting process once validated, and the remaining true gaps went to outreach teams as a prioritized list.

Common Errors

  • Treating a data gap as a care gap and spending outreach effort on it
  • Supplemental data with the wrong code or date, so it is ignored
  • Member matching failures between plan and provider records
  • Late data feeds that miss the reporting cutoff
  • No record of the source and timing of supplemental data for audit

At a glance

  • Setting: Medicaid health plan
  • Focus: separating care gaps from data gaps
  • Output: a prioritized list of what to fix and who fixes it
  • Details are generalized. No client names, and no results are claimed that are not described here.
