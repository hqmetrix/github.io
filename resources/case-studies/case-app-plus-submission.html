Case study

Submitting APP Plus quality measures: collection, remediation and submission

An ACO with several practices and EHRs needed one defensible submission for its clinical measures.

Case Studies · Anonymized · Last checked November 17, 2026

← Case Studies

Problem

The ACO's practices used different EHRs. Each could produce its own measure report, but the reports disagreed with one another, patients appeared in more than one practice, and nobody could say with confidence whether each measure met the 75% completeness requirement.

Required Data

  • Patient demographics and attribution lists
  • Encounters in the measurement period
  • Diagnoses, problem lists and exclusion reasons (hospice, advanced illness, and similar)
  • Results and observations: blood pressure, HbA1c, screening results
  • Procedures and orders: colonoscopy, mammography, depression screening and follow-up
  • Practice, provider and TIN identifiers for roll-up

FHIR Sources

  • Patient and Encounter for the population and visits
  • Condition for diagnoses and exclusions
  • Observation for vitals, labs and screening scores
  • Procedure and DiagnosticReport for screenings
  • Practitioner and Organization for practice roll-up
  • Where a practice had no usable FHIR API, a database or file extract mapped to the same elements

QRDA Generation

Patient-level data was standardized first and measures were calculated once across the whole ACO. The aggregate files for CMS were then built from that single calculation, as QRDA III or QPP JSON, instead of stitching together each practice's own aggregate file.

Validation

  • Completeness by practice and measure against eligible patients, each month.
  • A sample of patients traced from source record to final result, with every difference explained.
  • Comparison of each EHR's native measure result with the independent result.
  • CMS pre-submission tools run on every file.

Submission

A test file was uploaded before the window opened, then the final file was submitted with time to review the QPP dashboard. The collection type with the better expected score was chosen for each measure.

Common Errors

  • Duplicate patients across practices
  • Exclusions stored as free text
  • A practice on an older measure version
  • A late practice file that pulled completeness below the line
  • Wrong program name or submission method in the file

At a glance

  • Setting: multi-practice ACO
  • Measures: the five APP Plus clinical measures
  • Focus: completeness, accuracy and a clean upload
  • Details are generalized. No client names, and no results are claimed that are not described here.
