FHIR to eCQM Workflow: how digital measures fit with today's reporting

What FHIR changes for quality measurement, what stays the same, and a workable pipeline you can build now.

Blog · Last checked November 17, 2026

← Blog

Where things stand

Today's eCQMs continue to rely on the Quality Data Model, Clinical Quality Language, the Health Quality Measure Format and QRDA. CMS and its partners are moving toward digital quality measures that use FHIR and supporting implementation guides to represent clinical data, define measure specifications and exchange results.

A pipeline you can build now

  1. 1. Collect FHIR dataRead patient, encounter, condition, observation, procedure, medication and immunization resources from each source system's FHIR API, using bulk export for populations where supported.
  2. 2. Conform to QI-CoreCheck that each resource carries the profile and coded values the measure expects.
  3. 3. Evaluate measuresRun the CQL for each measure in a measure engine against the population and keep patient-level results.
  4. 4. Produce resultsCapture individual and summary results as measure reports, and keep the patient-level detail.
  5. 5. Convert for submissionToday, create QRDA III or QPP JSON for CMS. CMS provides tools that convert QRDA III to QPP JSON.
  6. 6. ValidateCompare against the source systems' own eCQM results and CMS's validation tools.

CMS has a prototype measure calculation tool that assumes a provider site system exposing data through a US Core or QI-Core compliant FHIR server.

Why build it this way

  • You get patient-level results you can trace and use for gap lists.
  • One calculation replaces many vendor-specific ones.
  • The same data prepares you for FHIR-based reporting when it arrives.
What is not settledCMS has indicated an intent to move to mandatory FHIR-based reporting later in the decade, but timing for ACOs is still being set through rulemaking. Do not retire today's pipeline until CMS says so.

At a glance

  • Today's eCQMs rely on QDM, CQL, HQMF and QRDA
  • Digital quality measures use FHIR for data, specification and reporting
  • CQL stays as the measure logic language
  • Submission to CMS is still QRDA III or QPP JSON
